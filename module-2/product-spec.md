# TaskFlow — Mini Kanban Board Product Specification

## 1. Overview

TaskFlow is a small personal Kanban board for tracking work items through three stages: To Do, In Progress, and Done.

The application helps a single user quickly see what needs to be done, what is currently being worked on, and what has been completed. It is designed as a focused full-stack learning project with a web frontend, a REST API backend, persistent storage, and automated tests.

## 2. Target User

A single person who wants a lightweight way to organize personal tasks or a small set of work items.

## 3. Problem Statement

People need a simple visual way to track the progress of tasks. A plain list does not clearly show whether a task is pending, currently active, or finished.

TaskFlow solves this by displaying tasks in status-based Kanban columns and allowing users to create, edit, move, and delete tasks.

## 4. Goals

- Provide a board with To Do, In Progress, and Done columns.
- Allow the user to create a task with a required title, an optional description, and a selectable initial status.
- Allow the user to view all tasks in their current status column.
- Allow the user to edit a task's title and description.
- Allow the user to change a task's status.
- Allow the user to delete a task.
- Persist task data so it remains available after the backend restarts.
- Provide a documented REST API contract and automated tests for core behavior.

## 5. User Stories and Acceptance Criteria

### US-1: View the Kanban board

As a user, I want to see a board with tasks grouped by status so that I can understand my work at a glance.

Acceptance criteria:
- The page displays exactly three columns: To Do, In Progress, and Done.
- Each task appears in exactly one column.
- A task is displayed in the column that matches its current status.
- An empty column displays a clear empty-state message.
- The board loads tasks from the backend API.

### US-2: Create a task

As a user, I want to create a new task so that I can add work to my board.

Acceptance criteria:
- The user can open a create-task form from the board.
- The form requires a title.
- The description field is optional.
- The user can select an initial status: To Do, In Progress, or Done.
- The initial status defaults to `todo`.
- The title must contain at least one non-whitespace character.
- A valid submitted task is created with the status selected by the user.
- After successful creation, the task appears in the column matching its selected status without manually refreshing the page.
- If the API rejects the request, the user sees an understandable error message.

### US-3: Edit a task

As a user, I want to edit a task so that its information remains accurate.

Acceptance criteria:
- The user can open an edit form for an existing task.
- The edit form is pre-filled with the task's current title and description.
- The user can change the title and/or description.
- The title remains required after editing.
- After a successful update, the board displays the updated task information.
- The task remains in its existing status unless the user changes its status separately.

### US-4: Move a task between statuses

As a user, I want to change a task's status so that the board reflects its progress.

Acceptance criteria:
- Each task provides a way to select a different status.
- A task can move from To Do to In Progress or Done.
- A task can move from In Progress to Done or back to To Do.
- A task can move from Done back to In Progress or To Do.
- After a successful status update, the task appears in the correct column without manually refreshing the page.
- The backend rejects status values outside `todo`, `in_progress`, and `done`.

### US-5: Delete a task

As a user, I want to delete a task so that obsolete work items no longer clutter my board.

Acceptance criteria:
- Each task provides a delete action.
- The user must confirm before a task is permanently deleted.
- After successful deletion, the task no longer appears on the board without manually refreshing the page.
- Attempting to delete a task that does not exist returns a not-found response from the API.

## 6. Functional Requirements

### Task fields

Each task has:
- `id`: unique integer identifier generated by the backend.
- `title`: required text, trimmed before storage.
- `description`: optional text.
- `status`: one of `todo`, `in_progress`, or `done`; supplied by the user when creating a task and defaults to `todo` when omitted.
- `created_at`: timestamp assigned when the task is created.
- `updated_at`: timestamp updated whenever the task changes.

### Data persistence

- The backend uses SQLite for local persistent storage.
- The backend accesses the database through SQLAlchemy.
- Tasks remain available after the backend application restarts.

### API behavior

- The frontend communicates with the backend over HTTP using a REST API.
- The API contract is documented in `openapi.yaml`.
- The frontend keeps API calls in a dedicated service layer.
- The backend validates request data and returns useful HTTP status codes.
- The backend returns JSON responses.

## 7. Non-Goals

The initial version does not include:
- User accounts, authentication, or authorization.
- Multiple users or shared/collaborative boards.
- Multiple boards, projects, workspaces, or teams.
- Task comments, attachments, labels, due dates, assignees, or priorities.
- Drag-and-drop task movement.
- Notifications, email integration, or real-time updates.
- Production deployment, cloud database hosting, or mobile-native applications.

## 8. Success Criteria

The project is complete when:
- A user can create, view, edit, move, and delete tasks through the frontend.
- The frontend uses the backend API rather than hard-coded task data.
- The backend implementation conforms to `openapi.yaml`.
- Data persists in SQLite across backend restarts.
- Automated tests cover the core API behavior and validation failures.
- The repository documents how to run the frontend, backend, and tests.
- The repository includes an AI usage report.

## 9. Future Enhancements

Potential future improvements include:
- Drag-and-drop movement between columns.
- Task priorities, labels, due dates, and filtering.
- Multiple boards.
- User authentication.
- Shared boards and real-time collaboration.
